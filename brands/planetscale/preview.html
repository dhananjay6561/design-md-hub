05 — Guardrails

Tone & Usage Rules

PlanetScale's precision aesthetic is fragile — one soft corner or errant orange breaks the signal. These rules are load-bearing.

✓

DO

  • ✓ Use #f35815 (orange-500) for one thing only: primary actions, active states, and brand moments.
  • ✓ Keep button labels short — maximum 3 words. "Get started", "Deploy", "Connect".
  • ✓ Use monospace for code, data, branch names, and keys — the font stack communicates precision.
  • ✓ Communicate status exclusively with the status palette — green/red/yellow. Never orange for status.
  • ✓ Use 1px border-primary (#414141) borders to define structure — more precise than shadow.
  • ✓ Default to dark mode in any embedded widget, screenshot, or code example.
  • ✓ Maintain 4px border radius on all interactive elements — consistency is load-bearing.
✕

DON'T

  • ✕ Don't use orange for more than one purpose — mixing it into status, hover, and decoration destroys its signal value.
  • ✕ Don't use font-weight: 700 (bold) in brand-facing copy — semibold (600) is the maximum.
  • ✕ Don't round corners beyond 4px in product UI — rounded-lg/xl reads as consumer-app softness.
  • ✕ Don't use heavy drop shadows in dark UI — elevation = the #111111 → #1a1a1a background step.
  • ✕ Don't place text on orange except in white — orange-on-orange-tint fails contrast thresholds.
  • ✕ Don't use purple (#a18bf5) outside Postgres-specific contexts — reserved semantic differentiator.
  • ✕ Don't add decorative illustrations — use 3D renders and data-driven diagrams only.
