The world's home for code — a developer collaboration platform where functional density and open-source culture shape every design decision. Primer is built on functional clarity: ornamentation is minimized, information density is respected, and every component earns its presence by serving workflow.

Tone & Guardrails

do / don't
DO
  • ✓Use semantic tokens (--fgColor-danger, --bgColor-success-muted) — not raw hex values
  • ✓Use --fgColor-default for all primary text
  • ✓Use --fgColor-muted for timestamps, metadata, and helper text
  • ✓Use --fgColor-accent for all text links — never a different color
  • ✓Use weight 600 for button labels, headings, and emphasized UI text
  • ✓Use the monospace stack for code, SHAs, file paths, and terminal output
  • ✓Reserve primary buttons for one-per-context actions
  • ✓Use 6px border radius as default for all interactive elements
  • ✓Keep line widths under ~80 characters for readable prose
  • ✓Align text left with ragged right — never justify body text
DON'T
  • ✕Don't use color as the only signal — always pair with a label, icon, or pattern
  • ✕Don't use raw hex values — always use design tokens
  • ✕Don't use more than one primary button in a single action group
  • ✕Don't use the Danger button without a confirmation step
  • ✕Don't use arbitrary font weights — only 300, 400, 500, or 600
  • ✕Don't center-align body text — Primer explicitly discourages it
  • ✕Don't animate decoratively — all motion must be functional, under 300ms
  • ✕Don't use orange for general highlighting — it maps to the severe role
  • ✕Don't use purple outside the done/merged state context
  • ✕Don't override hover/focus states — Primer's focus ring must remain intact
