05 — Guidelines

Tone & guardrails

Stripe's voice is authoritative through restraint, not heaviness. These rules preserve the integrity of the system.

Do
  • ✓
    Use #0A2540 deep navy for all primary text — never pure #000000.
  • ✓
    Apply #635BFF brand indigo to exactly one primary action per view.
  • ✓
    Weight 300 for display headlines; weight 400 for all UI text.
  • ✓
    Set negative letter-spacing (−0.015em to −0.030em) on all display and heading text.
  • ✓
    Keep cards on #FFFFFF against #F6F9FC backgrounds to create clear elevation.
  • ✓
    Use font-variant-numeric: tabular-nums for all monetary and numeric data.
  • ✓
    Maintain a 3px focus ring (rgba(99,91,255,0.10)) on every interactive element.
  • ✓
    Use badges as pill shapes with color + border — never fill-only.
  • ✓
    Allow generous vertical whitespace — 24px minimum between dashboard components.
  • ✓
    Use Source Code Pro for API keys, code samples, and terminal output.
Don't
  • ✕
    Don't use indigo for decorative purposes — reserve it for interactive and brand focal points.
  • ✕
    Don't apply bold (600+) weights — authority comes from restraint, not heaviness.
  • ✕
    Don't use warm shadows (rgba(0,0,0,...)) — always use rgba(10,37,64,...) cool-toned shadows.
  • ✕
    Don't collapse padding below 8px on interactive elements — precision tap targets matter in finance.
  • ✕
    Don't use more than two semantic colors on a single card or panel.
  • ✕
    Don't stack indigo CTAs — one primary action per surface, others secondary or ghost.
  • ✕
    Don't use border-radius above 16px on data-heavy containers — large radii signal marketing, not precision UI.
  • ✕
    Don't rely on color alone to communicate status — always pair badge color with a text label.
  • ✕
    Don't use full-black (#000000) text, backgrounds, or borders anywhere.
  • ✕
    Don't apply drop shadows to inline elements, text, or icons — shadows are structural, not decorative.
