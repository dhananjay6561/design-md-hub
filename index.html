What this is, where the data comes from, and how to plug it into your workflow. Still curious? Open an issue.

A growing wall of DESIGN.md files — one per brand. Each documents a real product's design system in plain text: colors, typography, spacing, components and the guardrails that keep usage on-brand. Every brand also ships a self-contained preview.html so you can feel the identity, not just read it.

Every spec is reverse-engineered from the brand's live production site — the real fonts they load, the exact hex values in their CSS, their actual logo SVGs and marketing copy. No guesswork, no stock palettes. If a value can't be confirmed from the live source, it's left out rather than faked.

100% open source and on GitHub. No paywalls, no sign-up, no API keys — clone it, read it, fork it, ship it.

Point your agent — Cursor, Claude Code, v0, Copilot, whatever — at a brand's DESIGN.md and ask it to build UI in that system. Because the tokens and guardrails are already structured, the agent generates on-brand components instead of generic ones. Plain text is the perfect context format for LLMs.
